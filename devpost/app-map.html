What the app is

A retro memory card game with Rick and Morty characters. You play up to 5 levels against a game AI that only remembers the cards it has seen, and remembers more each level (20% at level 1, 95% at level 5). On each AI move, Jev (TypeSafe) picks the card and reports its confidence. If Jev is unsure, slow, or missing, a local rules player decides, so the game never breaks.

The main pieces:

  • Game engine (src/game/): the pure rules for turns, pairs, levels, and scoring. It has no screen code.
  • AI (src/ai/): the imperfect memory (the kernel), the rules player, and the code that asks Jev.
  • Server function (api/): runs on Vercel, holds the TypeSafe key, and calls Jev.
  • Screen (src/ui/ + src/main.ts): draws the board, the pointing hand, and the modals, and runs the turn loop.
  • Services (src/services/): character images, saving the game in the browser, and the Jev client.

1The turn loop

src/main.ts, search for runAiTurn. While it's the AI's turn, this loop asks for a pick, updates the "AI brain" label with setBrain, moves the hand to the card, and flips it. Jev is asked while the AI "thinks", so Jev's delay doesn't add to the wait.

2The decision and the safety net

src/ai/aiPlayer.ts, search for buildView and chooseAiPick. buildView collects only what the AI remembers, so Jev never sees the whole board. chooseAiPick asks Jev and uses the answer only if the card can be flipped and the confidence is at least MIN_CONFIDENCE (0.5). Otherwise the rules player picks.

3The imperfect memory (the kernel)

src/ai/memory.ts, search for observe, which is called from flip in src/game/engine.ts. Every flipped card, yours or the AI's, gets a random roll. The AI keeps it only if the roll is below the level's aiRemember value in src/game/levels.ts.

To change this, start here

  • How well the AI remembers each level: aiRemember in src/game/levels.ts. Then run npm test, because src/ai/kernel.test.ts checks the level 1 vs level 5 contrast.
  • Cards per level or reveal time: cards, pairs, and revealMs in src/game/levels.ts.
  • When Jev's answer is trusted: MIN_CONFIDENCE in src/ai/aiPlayer.ts, and JEV_TIMEOUT_MS in src/services/jevClient.ts.
  • What Jev is asked: buildJevRequest in api/_lib/jev.ts.
  • The "AI brain" label text: setBrain in src/ui/columns.ts.
  • Welcome modal text and look: showWelcome in src/ui/modals.ts, and the .welcome rules in src/styles/main.css.
  • Colors, font, and borders: the variables at the top of src/styles/main.css.

A practice to reuse

Treat an AI model's answer as a suggestion to check, not a command to follow. Jev's choice goes through two checks before it's used: can this card actually be flipped, and is the confidence at least 50%? A timeout, an error, or a missing key sends the move to a plain rules player. The evidence is in src/ai/aiPlayer.test.ts, whose tests cover the confident answer, low confidence, an invalid position, an error or timeout, and an unavailable endpoint. In play, the "AI brain" label shows which path each move took.

The same approach works in any project that calls an AI model: validate the answer against what's actually possible, set a confidence or quality threshold, keep a simple fallback that always works, write a test for each failure path, and make visible which path was taken.
